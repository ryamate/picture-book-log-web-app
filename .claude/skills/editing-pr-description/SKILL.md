# PR Description Editor

現在のブランチに対応するGitHub PRの説明文を、プロジェクトのPRテンプレートに基づいて生成・更新する。

## ワークフロー

### 1. 現在のブランチとPRの確認

```bash
git branch --show-current
gh pr view --json number,title,body,baseRefName
```

- PRが存在しない場合 → ユーザーに通知して終了
- mainブランチの場合 → ユーザーに通知して終了

### 2. テンプレート種別の判定

ブランチ名のプレフィックスからテンプレートを選択する:

| ブランチプレフィックス | テンプレート |
|---|---|
| `fix/`, `bugfix/`, `hotfix/` | Bugfix.md |
| `feat/`, `feature/` | Feature.md |
| 上記以外（`refactor/`, `docs/`, `ci/`, `style/`, `chore/`, `test/` 等） | Enhancement.md |

テンプレートファイルの場所: `.github/PULL_REQUEST_TEMPLATE/`

### 3. 変更内容の分析

以下の情報を収集する:

```bash
# ベースブランチとの差分（コミット一覧）
gh pr view --json commits

# ベースブランチとの差分（ファイル変更）
gh pr diff
```

### 4. スクリーンショットの撮影（UI変更がある場合のみ）

UI変更を含むPRの場合、Playwright CLIでスクリーンショットを撮影し `docs/screenshots/` に保存する。
UI変更がない場合はこのステップをスキップする。

**前提条件:**
- フロントエンド開発サーバーが起動済み（`http://localhost:5173`）
- バックエンドAPIサーバーが起動済み（`http://localhost:8080`）
- 起動していない場合はユーザーに起動を依頼する

**撮影手順:**

1. 変更の影響を受けるページを特定する（diffから判断）
2. `frontend/` ディレクトリで Playwright CLI を実行する

```bash
cd frontend

# 認証不要なページの場合: Playwright CLIで直接撮影
npx playwright screenshot http://localhost:5173/<ページパス> ../docs/screenshots/<ページ名>.png --full-page
```

3. 認証が必要なページの場合はユーザーに手動スクショを依頼するか、Readツールでスクショファイルを確認する

**ファイル命名規則:**
- ケバブケースで、ページの内容がわかる名前にする（例: `login.png`, `dashboard.png`, `bookshelf.png`）

**撮影した画像の確認:**
- Readツールで画像ファイルを読み込み、表示内容を確認する

### 5. テンプレートの埋め込み

テンプレートファイルを読み込み、以下のルールで各セクションの内容を記載する:

**記載ルール:**
1. HTMLコメント（`<!-- ... -->`）はそのまま残す
2. HTMLコメントの下に実際の内容を記載する
3. テンプレートの構造（見出し、セクション順序）を崩さない
4. diffを見れば明らかな内容は省略し、「なぜ」「どう判断したか」を中心に書く
5. スクリーンショットセクションはUI変更がなければ「なし」と記載する
6. チェックリストはそのまま残す（チェックは入れない）

**セクション別の記載指針:**

- **関連リンク**: PRに紐づくIssueがあれば `closes #番号` 形式で記載
- **概要**: 変更の目的・背景を1〜3文で簡潔に
- **原因**（Bugfixのみ）: バグの根本原因をコードレベルで説明
- **変更内容**: 主要な変更点を箇条書きで。diffで自明でない設計判断を補足
- **スクリーンショット**: UI変更がある場合はステップ4で撮影した画像を埋め込む（下記形式）。なければ「なし」
- **備考**: レビュアーに特に見てほしい点、影響範囲、リリース時の注意点など

**スクリーンショットの埋め込み形式:**

```markdown
| 変更前 | 変更後 |
|--------|--------|
| （該当なし or 前回のスクショ） | ![ページ名](docs/screenshots/<ページ名>.png) |
```

**注意:**
- スクリーンショットファイルはコミットに含める

### 6. PRの更新

生成した説明文でPRを更新する:

```bash
gh pr edit <PR番号> --body "<生成した説明文>"
```

**bodyの渡し方**: ヒアドキュメントを使用して正確にフォーマットを維持する:

```bash
gh pr edit <PR番号> --body "$(cat <<'BODY_EOF'
生成した説明文
BODY_EOF
)"
```

### 7. 検証

更新後に内容を確認:

```bash
gh pr view <PR番号> --json body -q '.body'
```

確認項目:
- [ ] テンプレート構造が維持されている
- [ ] HTMLコメントが正しく残っている
- [ ] 内容がdiffと整合している
- [ ] チェックリストが残っている
